こころがまえ

  • まず本物を見る ― 想像だけで動かさない。
  • 調べる ― 論文や解説から、具体的な事実を5〜10個メモ(時間の比率、どこが先に動くか、何が揃って何がバラバラか)。
  • 目分量じゃなく測る ― ルールを毎フレームチェックする小さなスクリプトを書く。
  • 小さく直す ― バックアップ(index_v1.html, v2…)を残し、1回に1つずつ、相手の言葉をもとに直す。
  • 残った粗は正直に ― できたこととまだのことをセットで報告。

ステップ

  1. 見せたい場面を決める ― 待機・手を伸ばす・食べる・向きを変える・泳ぎ去る…などを並べて、時間割(タイムライン)を作る。
  2. 動きを調べる ― たとえば:
    • 誰が先に動く? タコのジェットは体が先で腕は後ろ。魚は頭から尾へ波が流れる。人は腕と脚が逆に振れる。
    • 時間の比率 タコの腕泳ぎは「ゆっくり開いて速く閉じる」、開く時間は閉じる時間の約2.5倍。
    • 波の伝わり方 曲がりは根元→先端へ。速さはまっすぐ一定じゃなくベル型。
    • ばらばら感 手足は半分自律。本物が揃うとき(パワーストロークなど)以外は完全同期しない。
    • 役割 探る腕・支える腕・漂う腕。ピンとまっすぐなポーズは「たまに」だけ。
    • おまけの動き 呼吸(3〜4秒周期)、曲がるときの水の抵抗による遅れ、先端のムチ、泡やほこり。
  3. 毎回同じ結果になるように作る ― window.renderFrame(frame) を用意して、乱数は種(シード)つきノイズに。動画化もチェックも何度やっても同じになる。
  4. チェックを入れる ― まっすぐな腕の本数、床へのめりこみ、カメラの急なジャンプ、画面から外れていないか、をフレームごとに数える。
  5. 動画にする ― ヘッドレスChrome(swiftshader)+ Puppeteer で1コマずつ撮って、ffmpeg で h264/yuv420p に。file:// ではなく http で配信して撮る。コンタクトシートと要所の静止画を作って、ちゃんと自分の目で見る。
  6. 見せて、感想を「原因」に翻訳 ― 「平泳ぎみたい」「棒みたいに硬い」「クモっぽい」などの言葉を、物理的な原因に置きかえて、必要なら調べ直して直す。
  7. よくある直し方
    • 動きが揃いすぎ → 手足ごとに位相とノイズを足す
    • 手足が硬い → 根元→先端の波、くるっと丸まり、遅れを足す
    • 回転がカチッとしてる → 手足のかきと水の抵抗の遅れで回す
    • 泳ぎ方が違う → 本物のストローク(いつ・どこが水を押すか)に合わせる
  8. 公開するときはメイキングも ― バージョンごとの感想・考えたこと・参考資料・残った粗・次の改善をまとめる。公開はアキヤさんのOKが出てから!

使った道具(タコさんの場合)

  • three.js 0.170 ― unpkg から importmap で読み込み(インストール不要)。
  • 自作のドラッグ回転 ― 指やマウスでくるくる回せるように。
  • CSS2DRenderer ― 部品ラベルや HUD(画面の計器表示)を HTML で重ねる。
  • InstancedMesh ― 腕のリング節(8本×58節)をまとめて軽く描く。
  • シードつきノイズ ― window.renderFrame を決定的(毎回同じ)にする。
  • ヘッドレスChrome + swiftshader + puppeteer-core ― 画面なしで1コマずつ撮影。
  • ffmpeg ― h264 / yuv420p で mp4 に(スマホでも再生OK)。
  • python http.server ― ローカルで http 配信して撮影・確認。
  • gh + GitHub Pages ― 公開(OKをもらってから)。
